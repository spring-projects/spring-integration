= What's New?

[[spring-integration-intro-new]]
For those who are already familiar with Spring Integration, this chapter provides a brief overview of the new features of version 7.2.

If you are interested in the changes and features that were introduced in earlier versions, see the xref:history.adoc[Change History].

[[what-s-new-in-spring-integration-7-2]]
== What's New in Spring Integration 7.2?

For more details, see the https://github.com/spring-projects/spring-integration/issues[GitHub Issues] that were resolved as part of the 7.2 development process.

In general, the project has been moved to the latest dependency versions.
Java 17 is still the baseline, but Java 25 is supported.

[[x7.2-new-components]]
=== New Components

A new `KafkaShareMessageDrivenChannelAdapter` provides a message-driven inbound channel adapter for Apache Kafka share groups (queues), built on `ShareKafkaMessageListenerContainer` from Spring for Apache Kafka.
See xref:kafka.adoc#kafka-share-inbound[Message-driven Channel Adapter for Share Groups] for more information.

A new `spring-integration-mqtt-client` module has been introduced to provide similar capabilities to the existing `spring-integration-mqtt`, but based on the HiveMQ MQTT client.
The Paho-based `spring-integration-mqtt` module is deprecated for removal in favor of this new module.
See xref:mqtt.adoc[] for more information.

A new `PayloadValidatingMessageSelector` accepts a message only if its payload passes a Spring `Validator`, such as a Bean Validation one from the `LocalValidatorFactoryBean`.
See xref:filter.adoc#filter-payload-validation[Validating Payloads] for more information.

[[x7.2-general-changes]]
=== General Changes

The `AllowListDeserializingConverter` now allows only a default list of framework and JDK types for Java deserialization, instead of allowing all classes when no patterns are configured.
The list is exposed as `AllowListDeserializingConverter.DEFAULT_ALLOWED_PATTERNS` and names each class explicitly.
`Number` subclasses are no longer allowed implicitly; only the listed number types are.
Common JDK exceptions, such as `IllegalStateException`, `IllegalArgumentException` and `IOException`, are included, so an `ErrorMessage` whose cause is one of them can still be deserialized.
This applies to every component built on the converter, such as the `PayloadDeserializingTransformer`, the `JdbcMessageStore`, the `JdbcChannelMessageStore`, the MongoDB message stores and the `SerializingHttpMessageConverter`.

IMPORTANT: This is a breaking change.
Applications that deserialize their own types (payloads, header values or custom exception types in stored `ErrorMessage` instances), including messages already in a store, get a `SecurityException` on read until those types are allowed.

Use `addAllowedPatterns()` to allow your own types in addition to the defaults, for example:

[source, java]
----
JdbcMessageStore store = new JdbcMessageStore(dataSource);
store.addAllowedPatterns("com.example.model.*");
----

Use `setAllowedPatterns()` to replace the defaults with your own list, or `"*"` to allow all classes again; use the latter only when all sources are trusted.
The `PayloadDeserializingTransformer` and the configurable MongoDB message stores now also provide `addAllowedPatterns()`.

The `DefaultErrorMessageStrategy` now preserves the original headers when building the `ErrorMessage`.
See xref:error-handling.adoc[] for more information.

[[x7.2-amqp-changes]]
=== AMQP Support Changes

The `wait-for-confirm` option on the outbound channel adapter now also works with simple publisher confirms.
When the message has no correlation data, the send is performed within the scope of a `RabbitTemplate.invoke()` operation and `waitForConfirmsOrDie()` is used.
A warning is now logged when the option is set but the connection factory supports no publisher confirms at all.
See xref:amqp/outbound-channel-adapter.adoc[] for more information.

[[x7.2-feed-changes]]
=== Feed Support Changes

The `FeedEntryMessageSource` now uses the feed's published date when none of the retrieved entries has an updated or published date.
Undated entries are again sorted after dated entries, so they are emitted together with new dated entries.
See xref:feed.adoc#duplicate-entries[Duplicate Entries] for more information.

[[x7.2-jdbc-changes]]
=== JDBC Support Changes

The `METADATA_VALUE` column in the `JdbcMetadataStore` schema scripts is now `NOT NULL`.
Existing databases created with older scripts should remove any null-valued rows and alter the column to `NOT NULL` when upgrading.
See xref:jdbc/metadata-store.adoc[] for more information.

On PostgreSQL, the `DefaultLockRepository` now adds `ON CONFLICT DO NOTHING` to its default insert query.
See xref:jdbc/lock-registry.adoc[] for more information.

JDBC tests and documentation no longer use Apache Derby.
Use H2 or HSQL for embedded testing.
`EmbeddedDatabaseType.DERBY` is deprecated in Spring Framework 7.1.
The `DerbyChannelMessageStoreQueryProvider` and `schema-derby.sql` are deprecated for removal.

The `<int-jdbc:message-store>` element has a new `allowed-patterns` attribute.
The comma-delimited patterns are added to the default allow-list, the same way as `addAllowedPatterns()`.
The mutually exclusive `allowed-patterns-override` attribute replaces the default allow-list instead, the same way as `setAllowedPatterns()`.
The `JdbcMessageStore` and `JdbcChannelMessageStore` now also provide `setAllowedPatterns()` to replace the defaults.

[[x7.2-http-changes]]
=== HTTP Support Changes

The `RestTemplate`-based configuration for the HTTP outbound gateway and outbound channel adapter (the `rest-template` attribute, and the respective Java DSL and constructor options) is now deprecated in favor of `RestClient`-based configuration, which also gains new options for configuring error handling.
The `SerializingHttpMessageConverter` now allows only the default framework and JDK types for deserialization, and has a new constructor that replaces these defaults with the given patterns of allowed classes.
See the xref:http.adoc[HTTP Support] chapter for more information about these and other changes.

[[x7.2-ftp-changes]]
=== FTP Support Changes

The FTP session factories can now connect through a proxy.
The `proxy` property of the `AbstractFtpSessionFactory` accepts a `java.net.Proxy` (SOCKS or HTTP), and the new `FtpHttpProxySessionFactory` tunnels the connections through an HTTP proxy that requires credentials.
See xref:ftp/session-factory.adoc#ftp-session-factory-proxy[Proxy Support] for more information.

[[x7.2-jms-changes]]
=== JMS Support Changes

Spring Framework's JMS `MessageConverter` implementations may now return `null` from `fromMessage()` when a JMS `Message` has no payload.
A `null` payload conversion is treated as a conversion failure, a `MessageConversionException` is then thrown.
This affects `AbstractJmsChannel`, `JmsDestinationPollingSource`, `ChannelPublishingJmsMessageListener`, and `JmsOutboundGateway`.
See xref:jms.adoc[JMS Support] for more information.

The `DefaultJmsHeaderMapper` can now be configured with the patterns of the message header names to map outbound to JMS properties, through its `setOutboundHeaderNames()` method.
See xref:jms.adoc#jms-header-mapping[Mapping Message Headers to and from JMS Message] for more information.
